# 开发路线图

## 第一阶段：数据与检索基础

目标：完成“能检索、能过滤、能解释来源”的知识底座。

### 任务

- 实现 `src/build_metadata.py`
- 实现 `src/extract_role_info.py`
- 实现 `src/generate_role_permissions.py`
- 实现 `src/build_vector_db_with_metadata.py`
- 实现 `src/retriever.py`

### 交付结果

- 结构化元数据文件
- 角色权限配置文件
- FAISS 索引文件
- 支持按角色过滤的检索器

### 验证方式

- 单元测试验证剧情顺序
- 检索样例验证权限过滤是否生效
- 检查返回结果是否保留正确来源信息

## 第二阶段：对话主链路

目标：完成从玩家输入到角色回答的最小闭环。

### 任务

- 实现 `src/chat.py`
- 新增 `src/prompt_builder.py`
- 接入 Ollama 调用本地模型
- 实现提示模板与上下文裁剪

### 交付结果

- `CharacterChat` 主类
- 可用的角色对话命令行版本或脚本版
- 可复用的提示词模板

### 验证方式

- 测试场景清洗逻辑
- 人工检查角色回复是否符合设定
- 记录平均响应时间

## 第三阶段：记忆、安全与状态管理

目标：提升系统稳定性与工程完整度。

### 任务

- 新增 `src/memory.py`
- 新增 `src/safety.py`
- 新增 `src/state_manager.py`
- 建立短期/长期记忆结构
- 增加输入过滤与拒答策略
- 设计知识版本迁移规则

### 交付结果

- 记忆读写接口
- 安全过滤模块
- 会话状态持久化方案

### 验证方式

- 多轮对话连续性测试
- 对抗输入测试
- 版本切换场景测试

## 第四阶段：服务化与演示

目标：让系统可展示、可测试、可接入外部引擎。

### 任务

- 新增 `src/api.py`
- 使用 FastAPI 提供对话接口
- 使用 Gradio 构建测试页面
- 设计 Unity/UE 调用示例

### 交付结果

- HTTP API
- Gradio 页面
- Unity/UE 接入说明

### 验证方式

- 接口联调
- 端到端对话演示
- 响应时间与稳定性统计

## 推荐优先级

如果接下来你希望按“最容易产出论文成果”的顺序推进，建议优先做：

1. `build_metadata.py`
2. `extract_role_info.py`
3. `generate_role_permissions.py`
4. `retriever.py`
5. `chat.py`

## 后续实现原则

- 优先把每个模块做成可单测的独立组件。
- 优先保留中间产物，如元数据 JSON、权限文件、检索日志，方便论文截图和实验分析。
- 优先让系统“可解释”，即每次回答都能说明它参考了哪些知识。
- 优先完成最小可运行链路，再逐步叠加记忆、安全和可视化界面。
