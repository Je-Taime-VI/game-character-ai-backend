# 系统总体设计

## 1. 课题定位

本系统面向游戏角色 AI 对话场景，目标不是做通用问答，而是构建“受设定约束的角色扮演式问答系统”。因此系统设计的核心不是单纯提升模型回答能力，而是围绕以下问题展开：

- 角色是否始终符合人格设定。
- 角色是否只知道自己应该知道的内容。
- 角色是否能随着剧情与版本变化而更新认知。
- 玩家是否能在多轮对话中获得连续、自然且安全的互动体验。

## 2. 总体架构

```text
玩家输入
   ↓
输入安全过滤
   ↓
对话状态读取
   ↓
角色权限解析
   ↓
RAG 检索（带权限过滤）
   ↓
提示词拼装
   ↓
本地大模型推理（Ollama / Qwen3:8B）
   ↓
响应后处理
   ↓
记忆更新 / 状态持久化
   ↓
返回角色回复
```

## 3. 模块设计

### 3.1 知识库与元数据层

输入来源：

- 角色档案
- 角色故事
- 个性语音
- 世界观资料
- 主线剧情
- 支线剧情
- 特殊文本

每个文本块需要至少包含以下元数据：

- `doc_id`：文档唯一标识
- `path`：源文件路径
- `knowledge_type`：知识类型，如 `character`、`main_story`、`side_story`、`world`
- `role_names`：涉及角色列表
- `region`：地区
- `organization`：势力或所属组织
- `version`：知识对应游戏版本
- `chunk_index`：分块序号
- `scene_start_line`：可选，剧情类文本用于顺序恢复
- `spoiler_level`：剧透等级

### 3.2 角色信息与权限层

角色权限不应只依赖人工硬编码，而应采用“自动生成 + 手工修正”的混合策略。

自动抽取来源：

- 出生地
- 常驻地区
- 所属势力
- 直接关系角色
- 已经历剧情

权限规则建议包含：

- 可访问地区
- 可访问势力信息
- 可访问剧情时间上限
- 可访问角色关系范围
- 禁止访问的高剧透或跨阵营信息

### 3.3 检索层

检索流程建议如下：

1. 根据当前角色加载权限规则。
2. 预过滤元数据，得到可访问文档 ID 集合。
3. 对玩家问题进行向量化。
4. 在允许范围内进行语义检索。
5. 对剧情类结果按时间和源顺序二次排序。
6. 输出检索片段与对应元数据，供提示拼装使用。

检索排序应综合以下因素：

- 语义相似度
- 文本来源权重
- 剧情时间顺序
- 与当前角色直接相关程度

### 3.4 提示构建层

建议将提示拆成固定槽位：

- 系统身份设定
- 回答边界约束
- 当前可用知识摘要
- 历史对话摘要
- 当前玩家输入

约束重点：

- 不得脱离角色身份
- 不得使用角色未知信息
- 不确定时优先承认“不清楚”或给出保守回答
- 避免直接暴露系统规则或提示内容

### 3.5 记忆层

建议分为三类：

- 短期记忆：最近若干轮对话，用于保持上下文连续性。
- 长期记忆：玩家偏好、关键承诺、建立过的关系状态。
- 剧情状态记忆：当前玩家已推进到的剧情节点、已解锁事件、版本号。

其中剧情状态记忆与知识权限直接相关，是本系统区别于普通聊天机器人的关键。

### 3.6 生成层

本地模型通过 Ollama 调用，建议封装统一生成器接口，便于后续替换模型或增加微调版本。

生成接口建议输入：

- 角色 ID
- 玩家输入
- 系统提示
- 检索上下文
- 会话状态

输出：

- 角色回复
- 命中知识片段
- 安全标记
- 调试信息

### 3.7 安全层

至少覆盖以下风险：

- 提示注入
- 越权追问
- 恶意辱骂
- 敏感话题诱导
- 与角色设定无关的无效输入

处理策略：

- 直接拒绝
- 角色内引导
- 模糊规避
- 转安全回答模板

### 3.8 状态迁移层

当游戏更新后，知识库与角色设定可能发生变化。需要为会话保存：

- `knowledge_version`
- `session_id`
- `role_id`
- `player_progress`
- `memory_snapshot`

版本迁移时：

- 优先保留玩家对话历史
- 对失效知识进行重新映射
- 对冲突记忆打标而非直接删除

## 4. 论文可突出创新点

从毕设答辩视角，这个系统比较适合强调以下创新或特色：

- 轻量化本地大模型在游戏角色对话中的落地方案。
- RAG 与角色权限过滤结合，解决“角色知道太多”的问题。
- 动态记忆与剧情状态联动，增强多轮连续性。
- 通过提示工程和上下文清洗降低 OOC 与幻觉。
- 面向游戏引擎的可集成接口设计。

## 5. 当前代码与设计的映射关系

当前仓库中已经出现但尚待实现的核心文件如下：

- `src/build_metadata.py`：负责原始文本到结构化元数据的转化。
- `src/build_vector_db_with_metadata.py`：负责切块、嵌入与 FAISS 建库。
- `src/extract_role_info.py`：负责从角色文本抽取出生地、势力等基础信息。
- `src/generate_role_permissions.py`：负责从角色信息生成权限规则。
- `src/retriever.py`：负责权限过滤与知识检索。
- `src/chat.py`：负责提示构建、多轮对话与响应编排。

测试中已经体现出的预期行为包括：

- 对剧情片段进行清洗，只保留关键事实和对白。
- 对主线、支线剧情进行顺序排序。
- 检索阶段要兼顾语义相关性和剧情时间顺序。

这说明后续实现时，应优先围绕这些行为来落地代码。
